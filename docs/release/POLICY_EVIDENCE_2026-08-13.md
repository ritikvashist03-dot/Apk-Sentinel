# APK Sentinel policy evidence snapshot — 13 August 2026

Status: engineering policy research only. It is neither legal advice nor a Google Play approval. The final submission must be rechecked in Play Console against the signed AAB and the actual production data flows.

## Current source configuration inspected

This snapshot inspected source only; it did **not** compile, install, or inspect a signed artifact.

- `app/build.gradle.kts` declares application ID `app.apksentinel.mobile`, `minSdk = 26`, `targetSdk = 36`, and `compileSdk = 37`.
- The merged release manifest is expected to include `POST_NOTIFICATIONS`, `INTERNET`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`, `QUERY_ALL_PACKAGES`, a non-exported `NetworkMonitorService` bound as `VpnService`, and an exported=false report `FileProvider`. This expectation comes from source manifests; artifact verification is still required.
- The service declares `android:foregroundServiceType="specialUse"` and `android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE`; it is not always-on in source. This is a design declaration, not proof that the service can run on a device or that Play will accept the subtype.
- `@xml/locales_config` lists `en` and `hi`; the app exposes an in-app language choice. Source inspection alone does not prove Android Settings, Android 12-and-lower behaviour, or Hindi quality.

## Dated official requirements and the submission consequence

| Area | Current official evidence | Required release evidence / unresolved consequence |
|---|---|---|
| Target API | From 31 August 2026, new phone/tablet apps and updates must target Android 16 / API 36 or higher. [Android Developers — target API requirement](https://developer.android.com/google/play/requirements/target-sdk) (page updated 7 August 2026). | The source value is aligned. The signed AAB/APK still needs an `aapt`/bundle inspection proving `targetSdk=36`; target alignment is not a release approval. |
| Broad app visibility | Google treats installed-app inventory as personal and sensitive information. `QUERY_ALL_PACKAGES` is allowed only when broad visibility is core user-facing functionality and a less broad approach is insufficient; a Permissions Declaration Form is required. [Play Console Help — QUERY_ALL_PACKAGES](https://support.google.com/googleplay/android-developer/answer/10158779?hl=en). | The final listing, in-app disclosure, Data Safety form, reviewer path, and declaration must identify the local installed-app inspection purpose, explain why package filtering cannot provide the complete outcome, and prove no sale/ads/analytics use. Reassess whether every Play build truly needs the permission. |
| VPN service | Every `VpnService` app must complete the Play declaration. Device security/firewall is a permitted exception category only when it is genuine core functionality; use must be documented in the listing, personal/sensitive data needs prominent in-app disclosure plus affirmative consent, and user traffic may not be manipulated for monetization. [Play Console Help — VpnService policy](https://support.google.com/googleplay/android-developer/answer/12564964?hl=en-EN). | Provide a 90-second-or-less reviewer video showing launch, full disclosure, accept and decline/re-entry paths, Android VPN consent, the active notification, Stop, and the core local-monitoring outcome. The source claim of no remote endpoint must be reconciled with the policy requirement to encrypt data to a VPN tunnel endpoint; record the actual tunnel boundary and obtain policy/legal review rather than assuming a local endpoint satisfies it. |
| Foreground service | Apps targeting Android 14+ need an appropriate manifest FGS type and matching normal permission; missing type/permission can throw at runtime. `specialUse` is for valid cases not covered by another type, requires a free-form manifest subtype, and is reviewed. [Android Developers — FGS types](https://developer.android.com/about/versions/14/changes/fgs-types-required). The FGS type also requires a Play Console App-content declaration. [Play Console Help — FGS declaration](https://support.google.com/googleplay/android-developer/answer/13392821?hl=en). | `specialUse` is a **review risk**, not an approved category. Demonstrate the user-perceptible, user-initiated session; the exact service subtype; no disallowed background start; notification/Stop; and declaration alignment. Do not use `systemExempted` merely because the product uses VPN: it has separate platform eligibility criteria. |
| Data Safety and user-directed PCAP/report sharing | All Play developers complete Data Safety and provide a privacy-policy link even when no data is collected. Purely on-device processing is not collection. User-directed transfer can be outside the Data Safety definition of “sharing” only when the action is specific and the user reasonably expects the recipient; IP-address handling must be assessed according to actual use. [Play Console Help — Data Safety](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en). | Before declaring “no collection/no sharing,” perform a full outbound audit covering redirect checks, user-selected report/PCAP exports, VPN metadata, threat-feed import/update, crash/diagnostic SDKs, and every version/region. A save/share choice does not remove the need for clear scope, recipient, sensitive-content and persistence disclosures. Never claim encryption-in-transit unless it covers every applicable off-device transfer. |
| Prominent disclosure | When personal/sensitive-data access is not reasonably expected, Play requires an in-app disclosure before collection/access, describing the data and use, followed by distinct affirmative action; a privacy policy or terms alone is insufficient. [Play Console Help — User Data](https://support.google.com/googleplay/android-developer/answer/10144311) and [prominent disclosure guidance](https://support.google.com/googleplay/android-developer/answer/11150561?hl=en). | Keep separate, immediately-before-use flows for package inventory, VPN metadata/traffic handling, raw capture, payload/TLS/root/streaming if shipped, and any external lookup. Capture a clean-device accept/decline/re-entry video and disclosure-version evidence. |
| Per-app language | Android 13+ provides `LocaleManager`; AndroidX provides compatible APIs for earlier versions. A manually configured `localeConfig` is a supported way to expose app languages in Settings. [Android Developers — per-app language preferences](https://developer.android.com/guide/topics/resources/app-languages). | Verify the `en`/`hi` locale configuration, Settings handoff, rotation/recreation, Android 26–32 fallback, and full Hindi resources on actual devices. This is platform guidance, not a Play content-quality approval. |
| AAB and signing | New Play apps publish as Android App Bundles. An AAB is a publishing format from which Play generates optimized APKs. [Android Developers — Android App Bundles](https://developer.android.com/guide/app-bundle). Play App Signing uses a distinct upload key and Google-held app-signing key; test what Play delivers via Internal App Sharing or generated APKs. [Play Console Help — Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756?hl=en). | Produce a release-signed AAB, enrol/configure Play App Signing, preserve upload and Play app-signing certificate fingerprints, and test Play-generated device APKs. A locally signed APK is only an interim test artifact, not proof of Play delivery. |
| Developer verification | Play packages must be registered for Android developer verification by 30 September 2026; Play Console identity verification and package registration are separate controls. [Play Console Help — registering Play package names](https://support.google.com/googleplay/android-developer/answer/16984799?hl=en). | Confirm the developer-account identity state and register `app.apksentinel.mobile` with the final signing certificate. This is an owner/Console action and is currently unverified. |

## Mandatory Play Console submission package

1. Final public HTTPS privacy-policy URL, legal publisher identity, support contact, exact Data Safety responses, and testable links.
2. `QUERY_ALL_PACKAGES` Permissions Declaration Form: core functionality statement, least-privilege analysis, local-only handling, disclosure screenshots/video, and reviewer instructions.
3. `VpnService` declaration: permitted device-security/firewall category only if truthfully demonstrated; listing wording; separate disclosure; 90-second-or-less accept/decline video; no-monetization statement; tunnel-boundary/encryption explanation.
4. Foreground-service declaration: exact `specialUse` subtype/use case and evidence that the foreground work is user-perceptible and user-started.
5. Data Safety matrix tied to a signed build and outbound network audit, including every optional feature and SDK. Do not reuse a “no data collected” answer without that audit.
6. Content rating, target audience, app access/reviewer instructions, screenshots/video from the signed candidate, and developer identity/package-registration evidence.
7. Release AAB, upload certificate, Play app-signing certificate, mapping/SBOM, source/build hashes, bundle validation, and test results from Play-generated APKs.

## Explicit unresolved policy blockers

- No signed artifact or merged-release manifest has been verified; source-only evidence cannot prove permission/API declarations or default states in the candidate.
- The `specialUse` FGS rationale and the local-only VpnService tunnel/encryption interpretation need a real-device evidence package and reviewer/legal confirmation.
- `QUERY_ALL_PACKAGES` necessity versus narrower Android visibility is not yet justified with a final, reviewer-testable least-privilege analysis.
- No completed Data Safety, Permissions Declaration, VpnService declaration, FGS declaration, developer verification/package registration, listing review, or clean-device reviewer video exists in release evidence.
- Raw PCAP/report sharing, redirect resolution, current network-retention behavior, threat-feed operations, and every future Sensitive Advanced capability require an exact final data-flow audit before public exposure.
